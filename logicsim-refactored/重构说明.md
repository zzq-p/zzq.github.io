# 重构结果与优化建议

## 已修复的问题

| 原版问题 | 重构处理 |
| --- | --- |
| 用手动状态计数判断表达式结束，可能忽略多余操作数 | 逐词元检查栈深度，结束时必须只剩一个结果，并指出出错位置 |
| 解析器用字符串同时表示变量与错误，导致单个变量或常量被界面当成错误 | 错误通过异常传递，编译结果统一为模型与统计数据 |
| 节点编号同时使用变量名、数字和常量，存在冲突 | 自动生成节点采用独立前缀；载入时规范化编号并检测冲突 |
| 修改节点名称时修改类型标签，可能破坏导出 | 业务类型保存在节点数据中，与名称、备注、显示标签分离 |
| 备注写入和读取使用不同字段 | 统一 `memo` 字段，模型往返保留 |
| JSON 解析失败会清空当前图形 | 校验通过后再替换模型，失败保留旧图，渲染异常时恢复旧模型 |
| 文件 MIME 为空时拒绝载入；保存文本可能不是当前图形 | 按文件内容解析，保存时从当前图形重新生成模型，使用 `.json` 扩展名 |
| 拖动位置在导出时丢失 | 保存 `position`；完整位置模型载入时不强制重新布局 |
| 滚轮事件读取兼容性有问题，多处坐标算法重复 | 使用标准 wheel 事件，统一缩放比例和坐标变换 |
| `body` 上解绑所有鼠标事件，可能误删其他处理器 | 专用指针事件维护拖动状态，增加取消和失焦处理 |
| 全局变量泄漏、重复函数、无对应 DOM 的 Select2 代码 | 闭包封装 UI，移除重复实现和未使用依赖 |
| 页面固定高度计算不一致，窄屏内容溢出 | Flex / Grid 布局、画布大小监听、窄屏纵向排布 |

## 算法和性能

原版先递归组合条件分支列表，再生成选择器图。重构后使用有序二元决策图，以变量首次出现顺序为顺序，并对相同分支去重、对逻辑运算缓存。只绘制最终结果可达的选择节点。

这会减少重复计算和重复图形，但不保证所有表达式均为多项式复杂度：决策图仍可能随变量数指数增长。加入词元、变量、节点和运算量上限，避免无界增长；没有宣称已经解决所有大图性能问题。

实测回归样例：30 个不同变量连续相与，生成 30 个选择节点，没有枚举全部 2³⁰ 个输入组合。

保留 JointJS / Backbone / jQuery / Lodash / Graphlib / Dagre 原站版本，移除未使用的 Select2、W3 CSS 和独立字体。第三方依赖没有升级，以控制本次兼容性范围。

## 验证记录

- Node.js 原生测试：9 组全部通过。
- 300 个可复现随机表达式，对每个表达式穷举 3 个变量的 8 种赋值，共 2400 次独立语义对照。
- 验证五种运算、单变量、常量、重复变量、对象保留名称变量、无效输入、编号冲突、JSON 往返、循环连线和规模限制。
- 浏览器开发预览：示例表达式生成 9 个节点、10 条连线；常量 `1` 正常生成。
- 浏览器验证：名称与备注编辑后类型不变，JSON 再载入后备注与位置保留；无效 JSON 后原有 9 个节点和 10 条连线仍在。
- 浏览器验证：缩放按钮生效，桌面和 390px 窄屏无页面水平溢出；检查过程中未见 JavaScript 错误日志。
- 导出按钮执行并显示完成状态；自动化浏览器的下载事件等待超时，因此未用下载落盘文件做独立校验。模型序列化及再载入已单独验证。
- 浏览器使用 HTTP 开发预览，未验证 `file://` 直接打开；手动连线、触屏拖动和超大图交互尚未做完整浏览器回归。

## 后续优先项

1. 增加撤销 / 重做，降低删除和重新布局的误操作成本。
2. 为较大表达式增加 Web Worker 后台计算与取消按钮；对大图采用分批渲染。
3. 建立持久化浏览器回归测试，覆盖文件选择、下载落盘、节点拖动和手动连线。
4. 单独评估图形库升级，检查许可、依赖安全和 API 兼容性；不与本次功能重构混在一起。
5. 如需用于教学，可扩展中缀表达式输入和真值表；这两项当前未实现。
